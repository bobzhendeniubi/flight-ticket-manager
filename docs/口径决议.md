## 权限

- **2026-09-06 · 动钱端点限财务岗**：核实（把钱定性为已核实）、撤销已入账认款、跨单转移、流水导入走 requireFinanceAccess；运营认款（人工确认 / 批量确认 / allocate）保留给 STAFF——0825 的「运营认款 → 财务核实」两闸不变。
  - **2026-09-10 补充 · 撤销收款放开运营自撤（折中口径）**：撤销一笔人工收款 = 财务岗，**或**「本人录入 + 财务尚未核实」。即谁录的款，在财务核实前自己可以撤销（纠正手误后重录）；财务已核实的收款仍只有财务岗能撤销。核实、跨单转移、流水导入**维持限财务岗不变**。
    原因：09-06 把撤销一刀切给财务后，运营当场录错一笔也得找财务，纠正手误的成本高过风险——未核实的钱本来还没进财务的账。
    实现：`POST /payments/:paymentId/reverse` 不再挂 requireFinanceAccess（挂着运营一律 403，自撤那条路进不来），逐笔判定落在 `reverseManualPayment`：录入人取 `gatewayPayload.confirmedBy`，核实状态取 `Payment.verifiedAt`；拒绝时 403「只能撤销自己录入且财务尚未核实的收款」/「该收款财务已核实，请联系财务撤销」。审计 `REVERSE_MANUAL_PAYMENT` 仍为 CRITICAL，after 增加 `selfReversal` / `verifiedBefore`，财务可事后筛出「运营自撤」的记录。
    不变的部分：对账认款来源的收款不走这条路（仍须去收款对账台撤销认款，那边才会把钱退回挂账池）；取消族放行、佣金闸、收款复核锁、退款倒挂闸一概照旧。后台按钮按同一口径显示——非财务岗只在「本人录入 + 未核实」那笔上可点，其余置灰带提示；核实与跨单转移按钮只对财务岗可点。
- **2026-09-06 · 代理改客户归属**：AGENT 不得改 CustomerProfile.primaryAgentId（改成谁都不行），只有 ADMIN/STAFF 能改归属；与 PATCH /orders/:id/agent 禁止 AGENT 一致。

- **2026-08-26 · 代理密码重置**：内部员工（ADMIN/STAFF）都可重置**代理**账号密码；重置内部账号（ADMIN/STAFF）仍仅 ADMIN——防员工借重置接管同事/管理员账号。重置后强制首登改密。
- **2026-08-25 · 航班维护岗**：航班/班次维护放开给「运营（STAFF 未设岗）+ 票务岗」：新建航班、新班次、批量加班次、批量改时刻、单班次改价/容量/时刻/上下架。仍仅 ADMIN：升舱差价/商务舱联动（定价敏感）、整线停售、批量删除班次、批量改容量、单班次删除（批量类爆炸半径大）。⚠️ 隐含约定：staffRole=null 即视为运营/通用岗。
- **2026-08-24 · 删单/回收站**：放开给 STAFF（没发管理员号）；强制改状态仍锁 ADMIN。
- **2026-08-24 · 账号**：一人一号、实名、按岗位配可见范围；共享号封存。
