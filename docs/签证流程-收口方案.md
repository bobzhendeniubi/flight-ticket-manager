# 签证流程收口方案 —— 按签证岗四态流水线重排

> 2026-08-30 拍板方向。起因：两单录成「需要签证 + 全员自备签」的矛盾组合，签证台看不到、
> 送签对不上数；签证岗给出的理想模型是一条流水线，比现状干净，本方案按它收口。

## 一、目标口径（签证岗原话翻译成系统语言）

> 「客人进单是需要签证就进入需要签证选项，自备签单机票就进不需要选项，电子签就进电子签选项，
> 我们送了签的不管是电子签或者单次签，只要确认了就进入已签证。只需要这四个选项。」

补充口径（同日签证岗追加）：

> 「只要是办签证，都是需要签证。如果有除开 15 天单次或者单办签证的特殊情况，
> 有颜色区分或者提示我们就可以。」

确认单回话后的**最终口径**（2026-08-30 晚，签证岗逐条回复）：

- **录单四个选项保留**（不需要/需要/电子签/已签证）——签证岗明确「代理不会选岔，我们现在
  也是这样」，砍两档的提议不采纳，录单下拉**一动不动**。
- **特殊情况彩色徽标**：电子签 / 非 15 天单次 / 纯签证单，由签证产品结构化字段派生；
  **加急不需要单独颜色**（签证岗原话）。
- **已签证的办结写入**：签证岗标「已送签」即算（**材料送出去就算**，签证岗定的时点），
  整单非自备签乘客全部已送签 → 订单自动置已签证。
- **对数口径**：送签人数按**乘客级已送签数**统计（只有我方送签才会有这个标记），
  录单选「已签证」（客人自带）的单不产生送签标记，天然不混入。
- **已送签后客人不办**：是否可退、退多少**由人为确认**（签证岗原话），系统不硬拦也不自动退。
- **混合单**（一单有人办有人自备）：不做新功能，签证台按**单人单独显示**即可（现状即是——
  乘客平铺、自备签乘客不显示）。

## 二、现状 → 新模型映射

| 现状 | 新模型 |
|---|---|
| 订单级 `visaStatus` 四枚举（NEEDED/E_VISA/HAS_VISA/NOT_NEEDED），录单四档可选 | **不动**（签证岗回话保留四档）；「不需要/已签证」联动自备签、否决建任务等既有口径全部保留 |
| 已签证只能录单人手选 | 增加**系统办结写入**：整单非自备签乘客全部标「已送签」→ 订单自动置已签证（留审计、可对称回退）；对数统计按乘客级已送签数，不受录单手选已签证影响 |
| 签证类型靠录单人选「电子签」档 | 电子签/非 15 天单次/纯签证单由签证**产品**结构化字段派生彩色徽标（录单电子签档仍在，徽标是补充展示，两边不打架） |
| 乘客级 `visaSubmissionStatus`（待处理/材料准备/已送签） | 不动。签证岗的「已签证」落在全员 CONFIRMED 的汇总上 |
| 乘客级 `visaExempt`（自备签，挂 ¥240/人） | 不动语义，**收窄露出**：仅混合单（一单有人办有人自备）展开逐位选 |
| 签证任务 VISA_APPLICATION | 不动；「不需要/已签证」不建新任务的否决口径保留（办结单确实不需要新任务） |

存量：实测库 HAS_VISA 订单 **0 条**（448 NOT_NEEDED / 57 NEEDED / 2 E_VISA），无数据迁移。
sales-web / miniprogram 不使用该枚举，改造只涉及 backend + admin-web。

## 三、改造项

### A. 录单不动 + 特殊情况徽标（第一期）

- 录单弹窗/批量创单的签证状态下拉、出行人「随套餐/自备签」下拉**全部保持现状**
  （签证岗回话：四选项保留，代理不会选岔）。既有联动（不需要/已签证→全员自备签）不动。
- 特殊情况徽标：签证台/订单详情按签证产品结构化字段亮彩色徽标——电子签、非 15 天单次、
  纯签证单（无航班）。默认 15 天单次不亮，特殊才显眼；**加急不加色**（签证岗回话）。
  产品字段缺失时沿用现有「·推测」标记，不把弱证据装成权威（此前审计指出过这个坑）。

### B. 「已签证」= 派生办结状态（第一期）

- 时点（签证岗定）：**材料送出去就算**——即现有「已送签」标记（乘客级 CONFIRMED），
  不等出签，不新增状态。
- 触发：签证台标记「已送签」时事件驱动检查——本单非自备签乘客全部 CONFIRMED →
  订单 `visaStatus` 自动写 HAS_VISA（留审计），列表/详情/导出徽标随之变绿。
- 撤销对称：任一乘客从 CONFIRMED 回退 → 订单从 HAS_VISA 回落原档（办结写入时把原档存进
  审计 before 字段，回退时读取）；录单人手选的已签证单没有办结审计记录，不受回退逻辑影响。
- 签证台筛选档**不动**（0828 五档口径刚按签证岗要求上线）。
- 对数：签证台加统计条——当前筛选范围内「已送签 x 人 / 待送 y 人」，x 即签证岗的送签总数。
  按乘客级已送签数统计：只有我方送签才有该标记，录单手选已签证（客人自带）的单不产生，
  数永远对得上。

### C. 已送签改自备的「人为确认」闸（第二期，钱的正确性）

- 现状漏洞：乘客送签进度非 PENDING 后仍可改回自备签，应收**静默**退 ¥240——批文成本已发生，
  没人看见这笔钱退了。
- 口径（签证岗回话）：是否可退、退多少**由人为确认**，系统不硬拦也不自动退。
- 闸门：`visaSubmissionStatus ≠ PENDING` 的乘客改自备签/换人清签证时弹确认：
  - 提示「该乘客已送签，批文成本已发生」；
  - 退费金额**当场填**（默认 0，上限 = 该乘客自备签减免额），必填原因，留审计；
  - 不确认不放行——把今天的静默退变成显式决定。
- 已送签后取消订单同理：退款流程里签证费单列出来让操作人确认，不再默认全退。

### D. 签证价格收敛一处（第二期，可维护性）

- 现状：¥240 散在每个套餐的 `selfVisaDeductCny` + 各签证产品价，改价要挨个套餐改，会漂。
- 收敛：套餐自备签减免额**默认读取**套餐所含签证组件的产品价（240）；套餐显式配了减免额则覆盖
  （留给特价团）。签证产品价上已有加急档位（240 不加急 / 350 加急），继续做唯一价格源。
- 节假日价：暂走「补收杂费」手工通道（现状即可），需求坐实后再加日期区间价，不预建。

### E. 防呆（第一期，随 A 顺手）

- 录单/编辑出现「需要签证 + 全员自备签」矛盾组合 → 琥珀提示「本单不会进签证台」，
  可提交但必须看见（本次两单事故的直接教训）。

## 四、分期与验收

| 期 | 内容 | 验收 |
|---|---|---|
| 一期 | B 办结派生 + 统计条 + A 徽标 + E 防呆 | 签证台标完「已送签」订单自动变已签证、回退对称；统计条人数=送签数；特殊签证类型有徽标（加急无色）；矛盾组合有提示；`npm run build` 双端 + 后端测试绿 |
| 二期 | C 人为确认闸 + D 价格收敛 | 已送签乘客改自备签弹确认、退额当场填且留审计；改签证产品价一处、套餐减免额跟随；单测覆盖钱路径 |

- 录单 UI 零改动（四选项保留），无需知会代理。
- 部署顺序：一期先上（纯口径，无钱风险），实测冒烟后再上二期（动钱，先测试环境过一轮）。
- 上线知会：只需告知签证岗两句话——标完已送签订单会自动变已签证；已送签的人改自备签会弹退费确认。

## 五、不做的

- 不动乘客级 `visaExempt` 的定价语义（服务端永不静默改钱，2026-08 拍板口径不变）。
- 不做假设性的节假日价格引擎（先手工通道，需求坐实再建）。
- 不追既往：本方案上线前按旧口径录的单不批量重算钱。
