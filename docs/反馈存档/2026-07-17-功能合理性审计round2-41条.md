## 一、高严重度（钱错 / 超卖 / 对客承诺失真）

### 钱 · 结算与资金反向流（本轮最大主题：只建了钱进来的路，没建钱回去的路）

**H1. 结算「预存款抵佣金」= 双吃代理**（Codex 首报，我方复核坐实）
平台欠代理佣金 5k、代理存款 100k → 结算 PAID 后应付清零 **且** 存款再扣 5k：`prepaymentOffset = min(netCommission, balance)`（settlements.service.ts:13-15,293-294），PAID 时 `newBalance = freshBalance − offset` + 负数 OFFSET 流水（:452-475）。存款是代理的钱（schema.prisma:250 "positive = credit，不许赊账"），不存在可抵的欠款场景。**代理一来一回损失 2×佣金。**
→ 立即停用该抵扣；"佣金转存款"应是余额**增加**的显式入账。

**H2. 负数结算静默沉没**：netCommission<0 时 payable/offset 双重钳 0（settlements.service.ts:293-294），负补偿记录 generate 时已绑 settlementId（:242-245），下期只取 `settlementId=null`（:229）→ 平台应追回的钱从所有账本消失。测试造出 -50 结算单但全套无"追回"断言。
→ 负净额转代理应收/结转下期。

**H3. 结算单快照三漏**：① DRAFT~APPROVED 期间订单退款，佣金翻 REVERSED 但结算单不重算、PAID 照旧发钱，且 summarizeReversals 只统计 amount<0，这条正数 REVERSED 审批 UI 不可见（settlements.service.ts:439-442,556-559）；② 月中提前 PAID → 同期迟到佣金/负补偿三头落空（PAID 挡 generate :79-81、下期窗口不含 :211-231、PAID 不可 VOID :44）；③ VOIDED 只解绑 ACCRUED，REVERSED 滞留废单（:484-489，中）。
→ PAID 前校验绑定记录含正数 REVERSED 即拒付；结算取数改"createdAt < 本期末 且 settlementId=null"滚动收口。

**H4. 代理余额抵扣不可退**：余额抵扣直接累进 `paidAmount`（orders.service.ts:2066-2087，Codex 裁决：这是主因），退款报价基数=paidAmount（lib/cancellation.ts:100-109）→ 订单退款时余额抵扣部分以现金退给客户、代理余额永不回补。`PrepaymentTxType.REFUND` 全仓零写入（设计了没建）、`Order.prepaymentOffset` 全仓无写入者（幽灵字段，清账公式恒 0 项）。
→ 退款按资金来源拆分：余额部分回补余额（写 REFUND 流水），现金部分立 Refund。

**H5. 死单迟到回调假 REFUNDED**：订单已 CANCELLED/PAYMENT_TIMEOUT 时网关回调把 Payment 直接标 REFUNDED，注释称"资金原路退回"——但 payment-adapters 无任何退款能力（payment-adapters.ts:45-49 仅创建+验签）、不建 Refund 行、不提醒财务。真钱在商户账上，账面说已退。注释自称"正确口径"，属**前提不存在的拍板**。（payments.service.ts:192-207）
→ 改进挂账池（source=死单迟到款）或建 REQUESTED Refund 走人工。

**H6. 挂账池 Receipt 反向流缺失**：① 认领错单**无撤销**（routes 全集只有 list/ledger/register/allocate/refund，receipts.routes.ts:28-59），认领可能连锁触发 PAID+计佣+履约，错了只能改库；② refund 出账**无凭证行**（只翻状态+refundNote，receipts.service.ts:358-396），ledger 只有进没有出，轧不平；③ **总账双计**：认领会建 SUCCEEDED Payment，ledger 又把全部 Receipt+Payment 拼一起（:152-191），一笔钱显示两条，按它汇总日进账翻倍；④ Receipt 无 agentId/channelId（schema.prisma:1357-1380 vs PaymentChannel.agentId :1330），代理专属码进账无法归属、跨代理认领零提示（Codex 裁决降中：统一码本就要跨单认领，缺的是渠道维度）。
→ 加撤销认领 + 出账流水行 + 认领 Payment 打标去重 + Receipt 记渠道。

**H7. 差价/折扣与佣金零联动**（中，定性按 Codex 裁决收口）：FEE/DISCOUNT 行与 adjustmentCny 全不计佣（orders.service.ts:6898-6900），手填价折扣后佣金仍按折前全价计提（:6922 baseAmount=系统全价）→ 平台多付佣金；补房差收入代理拿不到佣。**佣金基数缺一条拍板的业务规则，当前静默用商品原价。**→ 交老板/财务拍板基数口径。

### 库存 · 切位/锁位/开票

**H8. 切位 SeatAllocation 是假的**（上轮线索，本轮双方独立坐实为最重条目）

- 数学形状错：代理卖 1 座 sold+1 但切位 seats 不核销 → 散客池双扣（头注释"不重复占用"不成立）。

- 删班次守卫不查 ACTIVE 切位，`onDelete: Cascade` 静默清空代理切位合同（flights.service.ts:863-893; schema.prisma:597）。
- **手册还在说它是"演示版：刷新就没了，不写数据库"**（使用手册-后台.md:66-67）——运营照手册练手 = 真锁生产库存。
→ 短期：藏入口 + 改手册；长期：切位纳入扣座 CAS/锁位余量同一口径 + 代理下单核销 + 接回收 cron。

**H9. 下单吞光本人锁位**（Codex 首报）：下单把该 schedule+cabin 下本人**全部** ACTIVE 锁位标 CONSUMED，不看订单数量（orders.service.ts:771-791）。锁 9 张给两批客人、先下 3 张单 → 剩 6 张锁蒸发、座位回池任人买。

**H10. 混装购物车共用一套乘客集**（Codex 首报）：前后端 effectivePax 一致取 MAX（CheckoutPage.tsx:161-198; orders.service.ts:545-558），Passenger 只挂订单不挂行 → 机票2人+签证3人的合法购物车产出"2 座 3 人"的单，谁飞谁不飞无法表达，履约岗各自瞎猜。MAX 设计只对"同一批人"成立，购物车却允许装不同人群的交易。
→ OrderItem-Passenger 关联，或不同出行人集合强制拆单。

**H11. 取消族回流开票额度不复检**（中，Codex 裁决降格为依赖 H10 的组合洞）：force 回占座态时座位有 CAS 重占闸，开票三布尔不清零也不复检（orders.service.ts:3079-3093; assertTicketingCap 仅三处翻标记时跑）→ 正常单被容量闸挡住，混装"乘客数>座位数"的单可顶穿 Σcapacity。
**H11b. 旧 PATCH /orders/:id/invoice-status 半死端点**（Codex 建议升高）：无状态闸/软删闸，写的 invoiceStatus 额度计数/导出都不读（orders.service.ts:2870-2902; ticketing-cap.ts:16-18）→ 两本开票账互相矛盾；UI 无调用但任何 STAFF token 可打。→ 下线。
