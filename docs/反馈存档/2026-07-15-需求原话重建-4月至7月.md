## D. codex 的独立结论（「最该回去推翻的3条」）

> 1. **「汇率全删」** — 财务灾难源头。包机成本既然涉及实付汇率，就必须保留原币、汇率、人民币入账、付款日/锁汇日。只存 CNY 会让汇兑损益和成本责任无法审计。
> 2. **「实时单座成本 = 包机成本 / 已售座数，用来定价」** — 这个指标最多做保本警示，不能驱动售价。低销量时推高价格，进一步压低销量；高销量时降低成本线，又诱导后卖低价。会计成本应按总座位分摊，空座单列。
> 3. **「删除后自动退库存」** — 删除不能承担业务状态机。必须先取消/退款/释放座位和酒店，再软删隐藏。否则库存、钱、审计三条账会被一个"主管删除"动作同时绕过。

codex 与本次五路 agent **独立收敛到同样的三大主题**：汇率、成本口径、删除语义。分歧仅一处：codex 认为「所有岗位导出带金额」目前已被 `role=ticketing|visa` 裁列缓解（判中），agent 核到 `role` 来自 **query string 而非 `req.user.role`**、且 export 全线绕过脱敏 serializer，判高。**以 agent 为准**（有代码位）。

## E. 五个反复出现的病

1. **只修可见的那一半。** 拼房物理口径改了看板没改卖货（还把"两边一致错"变成"两边不一致"）、补房差收了钱房控还在配室友、批量开票补了上限没补状态闸、`physicalRemaining` 算好了摆在那儿就是不接到闸上。

2. **照抄解法，不照根因。** 赵姐的"现象"基本都真（销控不减、导出漏单、时刻改不了都实锤是 bug），但她给的"解法"几乎都是**旧系统的形状**（硬删、改日期格式、批量只限单机票、全看备注、收定金才上系统）。**这批里出事的，全是我们照抄了解法的地方。**

3. **"留痕"被当成防线。** 手填价 1 元能过、死单能抬 total、房差能重复收——都有审计，但审计是事后的、fire-and-forget 的、且在事务外。

4. **新加的列没有消费方。** 定金 4 列恒空、婴儿同行成人列没有 passengerType（婴儿占座收全价）、`gender` 在分房编辑器里只是个徽章、`infantCompanion` 全仓无人读。**满足了提需求的那个岗位的观感，把不变量留给了下游。**

5. **传话没传到位。** 汇率是老板 5-28 说删、财务 6-11 说要——两边都不知道对方说了什么，中间隔着我们。成本快照是财务以为有、我们文档写有、生产从来没写。

## F. 一句话结论

老板 6-15 立的那条纪律（「她的东西你得多question一下」「当成一个傻逼用户…以产品经理的思维先去理解她的需求」）是对的，但**方向使反了**：
