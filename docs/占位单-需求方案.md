# 占位单（留位 / 切位 / 散客占位）需求方案

> 状态：设计稿 v1（2026-08-23）。需求来源：代理组 + 操作部（团队留位流程）。
> 目标读者：产品/研发/财务。拍板记录见文末。

---

## 一、背景

现有系统所有创单入口都强制完整乘客名单（姓名/证件号/生日/护照有效期），
无法表达「先收钱占座、后补名单」的业务。实际存在三个场景：

1. **旅游团留位**：付定金 → 占位 → 付二定 → 付尾款 → 导入名单。
2. **代理切位**：付**全款**才占位（付款前不占，卖完自担），然后补名单。
3. **散客占位**：单张/套票客人暂时给不出证件信息，需要先占 1-2 座。

三者本质相同：**一个占座但没有名单的库存实体**，差别只在
「什么时候开始占座」和「收款计划长什么样」。因此做**一张「占位单」，
用收款模板区分玩法**，不做两套功能。

旧「切位（包位）」模块因未接入公共库存（专卖不专、会超卖）已停新建，
本功能是它的正确版，上线后旧模块下线。

## 二、核心原则：机制 vs 政策（SaaS 视角）

| 层 | 内容 | 举例 |
|---|---|---|
| **机制**（写死，人人一样） | 占位实体、库存扣减链、锁价+审计改价、分期引擎+过期折叠、取消清算=没收已付、占位消费式转正、提醒 | — |
| **租户配置** | 收款计划模板、超时动作、免损比例默认值 | 本司：定金300/人 当日，二定300/人 D-15，尾款 D-7；超时=仅提醒 |
| **单据覆盖** | 各期截止日手调、锁价修改、免损比例改 | 团队条件都是谈出来的，模板只是起点 |

任何一家公司的具体数字（300 元、15 天、10-15%）**不进代码**。

## 三、数据模型（草案）

```
HoldOrder 占位单
├─ id / holdNo（单号）
├─ ownerType: AGENT | CUSTOMER          归属代理或直客
├─ ownerId / groupName（团名，可空）
├─ flightScheduleId + cabin             一期只占机票舱位（往返=两条单，见§十一）
├─ seats: int ≥ 1                       初始占位数（免损额度基数，建单后不变）
├─ perSeatPriceCny: int                 锁定结算价（建单即锁，改价见§七）
├─ freeCancelRatio: decimal             免损减员比例（模板默认，单据可改）
├─ status: PENDING | HOLDING | OVERDUE | FULLY_PAID
│          | CONVERTED | RELEASED | CANCELLED
├─ seatsConverted: int                  已转正式订单的座位数
├─ seatsCancelled: int                  已减员座位数（含免损与扣损）
├─ freeCancelUsed: int                  已消耗的免损名额（跨阶段累计）
└─ installments[] 收款期
   ├─ seq / label（定金/二定/尾款…）
   ├─ amountRule: PER_PERSON_FIXED | REMAINDER   （PERCENT_OF_TOTAL 留接口）
   ├─ perPersonCny（按人头固定额时）
   ├─ dueDate                            建单时按模板算出，可手调
   ├─ status: PENDING | PAID
   └─ receiptIds[]                       挂现有认款流水
```

## 四、状态机

```
（切位模板：首期=100% 全款）
PENDING ──首期认款确认──► HOLDING ──全部期款确认──► FULLY_PAID ──名单导入──► CONVERTED
  │                        │  ▲                        │
  │                        │  └──补款──── OVERDUE ◄──任一期过期未付──┘（仅提醒模式）
  └─取消──► CANCELLED      └─超时(自动释放模式)/手工释放──► RELEASED
```

- **占不占座只看状态**：`HOLDING / OVERDUE / FULLY_PAID` 占座；
  `PENDING / RELEASED / CANCELLED / CONVERTED` 不占（CONVERTED 的座位已由订单承接）。
- 留位模板：首期=定金 → 定金认款确认即 HOLDING。
  切位模板：只有一期全款 → 全款确认才 HOLDING（**付款前不占位**，代理组确认口径）。
- `OVERDUE`：任一期过截止日未认款。仅提醒模式下**不释放座位**（业务拍板），
  但单据在工作台置顶飘红，且始终可手工释放/取消。自动释放模式下由 worker 转 RELEASED。

## 五、库存口径（正确性地基，不闭环不上线）

```
可售余量 = capacity − sold − 未过期锁位 − Σ(占座状态占位单的 占位余座)
其中 占位余座 = seats − seatsConverted − seatsCancelled
```

必须同步接入的读写点（漏一处 = 旧切位第二）：

1. 前台搜索 `flights.service` search / listSchedules（档位计算同口径）
2. admin 余位（航班管理 / 座位统计）
3. 套餐可用性 `bundle-availability.service`
4. **下单 CAS**：`sold + qty + locked + heldUnsold ≤ capacity`
5. 锁位创建的余量检查 `seat-locks.service`
6. 候补 `waitlist` 的余量判断

占位单转正时**消费自身座位**（不再走公共池扣减），与订单消费锁位同一模式，不会双扣。

## 六、收款计划引擎

### 模板（租户级）

每期 = `{label, amountRule, perPersonCny?, dueOffsetDays}`，dueOffsetDays = 起飞前 N 天
（首期 offset=∞ 表示「建单当日」）。本司模板：

| 期 | 金额 | 截止 |
|---|---|---|
| 定金 | 300/人 | 建单当日 |
| 二定 | 300/人 | 起飞前 15 天 |
| 尾款 | 总额 − 已收 | 起飞前 7 天 |

### 过期折叠（通用算法，替代所有「不足N天」特例）

建单时逐期算 `dueDate = 起飞日 − offset`；**所有 dueDate ≤ 建单日的期自动合并为首笔**。
- D-10 建单 → 二定截止已过 → 首笔 = 定金+二定（600/人），尾款 D-7 照旧
- D-5 建单 → 三期全并 → 全款留位
- 覆盖代理组口径「不足15天付定金+二定、不足7天全款」，零特例代码。

### 截止日调整

系统只算理论日并展示；涉及周末的顺延/提前**一期不做自动逻辑**，运营手调 dueDate 即可
（自动顺延规则留作后续租户配置）。

### 超时动作（租户开关）

`REMIND_ONLY`（本司，默认标 OVERDUE + 提醒引擎催收） / `AUTO_RELEASE`（worker 释放回池）。
提醒复用现有提醒引擎：每期截止前 N 天 + 过期当日。

## 七、锁价与改价

- 建单即锁 `perSeatPriceCny`（结算价），转正订单按锁价计价，不随出发日浮动。
- 改价 = ADMIN/STAFF 权限 + 必填原因 + 审计日志（业务确认「很少但存在」涨降价改结算价）。

## 八、取消 / 减员清算（机制：没收已付）

**扣损金额 = 该座已付的钱，无独立罚金配置**（代理组确认口径）：

```
perSeatPaid    = Σ(已确认期的人均额)                 // 付到一定=300，付到二定=600
freeQuota      = round(初始 seats × freeCancelRatio)  // 基数=初始人数，建单后固定不变
                                                      // 取整=四舍五入（已拍板）
freeCancelUsed = 历史免损减员累计（跨阶段累计消耗）

减员 n 座时：
  尾款未确认：
    免损部分 = min(n, freeQuota − freeCancelUsed)
      → 不没收：该座已付款**转为本单余额，抵扣剩余人尾款**（不退现金，已拍板）
    超额部分 = n − 免损部分                        → 每座没收当时的 perSeatPaid
  尾款已确认后：免损额度作废，任何取消每座全损（没收全部已付）
整团取消 = 减员 n = 剩余全部座位，同一公式。
  注：整团免损取消时无「剩余人」可抵 → 该场景款项去向需运营个案处理（系统挂账提示）。
```

**免损额度是一个跨阶段的池**（代理组确认）：基数永远是初始总人数，
一定阶段用掉几个、二定阶段接着用剩下的；额度耗尽后再减员，
按**减员发生时**已付到第几期扣（一定阶段损 300、二定阶段损 600）——
所以同一张单上「免损 + 损定金 + 损两定」可以并存，逐座清算。

清算由系统计算并出「减员/取消清算单」，运营确认后座位立即回池
（业务口径：确定取消就必须在系统取消留位）。没收款项**暂按默认口径单列
「违约金收入」**（不混入票款收入），会计科目财务后续有结论再改名目。

## 九、名单导入 → 转正式订单

- 复用**批量创单**的名单校验（护照有效期必填等全渠道口径原样保留），
  payload 加 `holdId`。
- 校验：名单人数 ≤ 占位余座；按 hold 锁价计价；订单记 `sourceHoldId`。
- **支持分批转正**（先导 18 人、剩 2 座继续占着），seatsConverted 累加；
  全部转正 → CONVERTED。
- 已认款项按人均结转到订单已收；差额进订单尾款。

## 十、与现有模块的关系

| 模块 | 关系 |
|---|---|
| 旧切位 seat-allocation | 本功能上线后下线；存量 ACTIVE 手工回收清零 |
| 认款 receipts | 期款全部走认款流水挂接，复用撤销/冲销闸 |
| 提醒引擎 | 催款提醒 |
| 批量创单 | 转正复用其名单校验与创单管线 |
| 锁位 worker (BullMQ) | 超时/释放 worker 同模式 |
| 房控 | 一期不联动（99% 团队只有机票）；订房团队走现有流程，二期再考虑占房 |

## 十一、分期实施

1. **一期：库存链**——HoldOrder 表 + §五全部读写点接入 + 手工建单/释放/取消 + 锁价。
2. **二期：收款计划**——模板引擎、过期折叠、认款挂接、提醒、OVERDUE/自动释放 worker、
   减员清算计算器。
3. **三期：转正与工作台**——名单导入转正（含分批）、占位工作台（占了几座/收到第几期/
   飘红催收）、租户模板配置页。

范围注：一期只支持**单程班次舱位**占位；往返团队建两条占位单（与旧切位同粒度）。
套票客人占位 = 占对应班次机票舱位，转正时走套餐创单（房态届时检查）。

## 十二、拍板记录与遗留问题

**已拍板**（2026-08-23，代理组口径）：
- 定金即锁结算价，改价少见但要支持（带权限+留痕）
- 定金当日 / 二定 D-15 / 尾款 D-7；超时**不释放占位**，仅提示收款日期
- 免损减员截止 = **付尾款之前**；免损比例 10-15%（单据可配）
- 免损额度基数 = **初始总人数**，跨阶段累计消耗；耗尽后按减员时已付额扣损
- 扣损 = 没收该座已付额（300 → 600 → 全损），无独立罚金
- 99% 团队只有机票；散客/套票无名单占位也要支持
- 免损取消的已收定金**不退现金，转本单余额抵扣剩余人尾款**
- 免损名额取整 = **四舍五入**
- 没收款会计科目：暂按默认——报表**单列「违约金收入」**，财务有结论再改名目

**遗留问题**：
1. 整团在免损范围内取消时（无剩余人可抵扣），已收定金去向个案处理，
   系统只挂账提示，不自动清算
2. 没收款会计科目名目待财务最终确认（默认口径已可开工）
3. 周末顺延自动规则、按百分比收款模板、占房联动 → 后续版本
