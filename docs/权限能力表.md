# 权限能力表

全站权限只有**一张表**：`backend/src/lib/capabilities.ts`。后端用 `requireCapability` /
`hasCapability` 判，前端用同一批能力 id 显隐（后台 `useCapabilities` / `<Can>`，前台
`lib/useCapabilities`），谁持有哪些能力由后端算好、随 `GET /users/me` 下发。

为什么要这张表：权限判断此前散在后端二十来个文件、前端十来个文件里，同一条口径两边各写一遍。
历史上因此翻过车 —— 只改后端半边，前端按钮还是灰的，运营报「没有权限」；反过来只改前端，
按钮亮了但一点就 403。2026-09-06 还出过一次反向的：前端写了一条后端没有的能力，
「航班管理」整页对所有人消失。

## 怎么改

1. 改 `backend/src/lib/capabilities.ts`（唯一真源）；
2. 同步 `admin-web/src/lib/capabilities.ts` 的 id 镜像 —— 漏了会被
   `capabilities.test.ts` 的「前端能力清单镜像与后端逐字一致」当场拦下；
3. 跑 `npm test --workspace=backend`：
   - `capabilities.matrix.test.ts` 的快照钉住「每个（角色, 岗位）能进哪些端点」，
     **重构期间一格都不许变**；真要改口径，单独一次提交、单独说明、单独刷快照；
   - `capabilities.test.ts` 的内联闸对照表逐条断言「新能力与替换前的角色判断式等价」；
4. 回来更新本文档。

## 受众一览

| 受众 | 谁持有 | 备注 |
| --- | --- | --- |
| `ADMIN_ONLY` | 管理员 | 仅管理员 |
| `OPS` | 管理员 · 内部员工（全部岗位） | 后台绝大多数运营功能 |
| `OPS_AND_AGENT` | 管理员 · 内部员工 · 代理 | 代理能自助的功能，数据另按代理树圈 |
| `ANY_AUTHENTICATED` | 任何已登录账号（含客户） | 守卫层只要求登录，口径在业务里逐单判归属 |
| `FINANCE` | 管理员 · 财务岗 | 对应原来的 requireFinanceAccess |
| `FLIGHT_MAINTENANCE` | 管理员 · 运营岗 · 票务岗 | 签证岗 / 房控岗 / 财务岗进不来 |
| `AGENT_ONLY` | 仅代理 | 代理自助专用入口 |
| `ADMIN_AND_AGENT` | 管理员 · 代理 | 内部员工反而进不去 |
| `VISA_DESK` | 管理员 · 签证岗 | 只有一处：确认改自备签申请 |

> 岗位（`staffRole`）只对内部员工有意义。留空 = 运营 / 通用岗，与显式的 `OPERATIONS`
> 枚举值处处同权（老账号仍是留空，不回填）。岗位逐请求从 User 表取回，改岗下一个请求即生效。

## 能力清单

「后端」列是挂了这条能力的路由与 service 文件，「前端」列是按它显隐的页面与组件。
「—」= 这条能力目前只在表里登记、还没有调用方。现在只剩三条：`orders.cancel`、
`orders.itinerary`、`payments.read` —— 这三件事没有独立的角色闸，谁能做由归属判定
（客户只能取消自己的单、代理只看自己树内），能力先占位，哪天要收紧再接线。

## 还没收进能力的地方

这些位置仍在直接读 `role`，都是**有意保留**的，不是漏网：

- **归属闸**：`assertCanView` / `assertCanTransition` / `resolveListOrdersWhere` 等按角色
  圈数据（客户只看本人单、代理只看自己与下级）。这是「看得到哪些行」，不是「能不能做这件事」。
- **通道选择**：`assertAgentSelfEditAllowed` 的自助窗口、换酒店与升舱的 `isSelfService` 分流、
  星级闸的 `isOperator`、改期的 `selfServiceCorrection` 旗子。能力在入口已经判过，
  这里选的是「按哪套规则走」。
- **视图口径**：全岗总表按岗位强制视图、代理视图强制、序列化脱敏的 role 上下文。
- **审计留痕**：`selfService` 标记、`actorFromRequest` 里的 role 透传。
- **订单页的批量工具条**：一个 `isOps` 管着二十来个动作，每个动作的能力各不相同，
  拆它是单独一件事。
