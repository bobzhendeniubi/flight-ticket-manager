跨单分房操作说明

两张订单合住一间房 · 三人间怎么处理 · 分房表当真值 · 房控 / 运营 · 2026-09-14

以前系统里的"房间"只能装本单的人，两张不同订单的客人要合住一间、或者三个人挤一间，都只能各自在自己单里备注一句、房控自己心里数着。现在有了「跨单分房」：把这间房在系统里立成真的，两张单的人一起进去，分房表、销控板、导出都认这个真值，不用再靠备注人工对。这份说明给房控岗和运营看，讲清楚在哪操作、怎么操作、几条要注意的规则。

一、这是什么，解决什么问题

两张不同订单的客人要合住一间房——最常见的是拼房：各自下的单，酒店那边是一间房两个人。以前系统里的"分房表"是挂在每张订单自己身上的，一个房间盒子只能装本单的人，两张单永远分不到一间去，房控只能靠备注手工记，导出的时候房号也对不上。三人间同理：本质就是"一张单的人 + 另一张单的人凑一间"，不是房型问题。

现在「跨单分房」把这间房在系统里立成一个独立的真值（内部叫"共享房"）：房控在工作台里把两张单（或更多）的人一起拖进同一个房间盒子，保存后这间房就是真的了——房控物理房怎么算、导出印几号房，都按它来，不用再靠备注对。三个人合住一间房，就是往一个房间盒子里拖三个人，系统按份额分摊房费和物理间数，不用凑"三分之一间"这种算法。

钱不会因为这次改动自动变化：谁多摊、谁少摊房费，是运营在工作台里手动定的"份额"，系统不替你算账、也不自动改结算价（见§四）。

二、入口在哪

「跨单分房」一共两个入口，打开的是同一个工作台：

  1. 房控页 →「订单分房（拖拽）」卡片：卡片右上角有「跨单分房」按钮，点开工作台默认带当前正在看的这张订单的酒店和入住区间。
  2. 销控板占房下钻：在房控页的酒店/日期矩阵里点某天某酒店的「余量」格子，弹出的占房抽屉里同样有「跨单分房」按钮，默认带这家酒店、这一天入住的区间。

入口一：房控页「订单分房（拖拽）」卡片右上角的「跨单分房」按钮

入口二：点销控板某天某酒店的余量格，抽屉里也有「跨单分房」按钮；下面已经合住的订单会多显示一行"跨单合住 X 间 · 本单计费份额 X · 去重物理房 X"（三个数口径不同，见下方提示条，不能互相加减）

三、操作步骤

  1. 打开「跨单分房」工作台，顶部选酒店、入住、退房三个条件（从入口带入的会自动填好，也可以自己改），点「刷新」拉数据。
  2. 工作台分两栏：左边是跨订单乘客池——这家酒店这个入住区间里，所有还没作废的订单的出行人，按订单分组列出来；右边是房间盒子——已经存在的共享房、以及可以新建的空房间。
  3. 把左边池子里的人拖进右边的房间盒子，一个盒子可以装来自不同订单的人。盒子里的人还是按"来源订单"分组显示，方便看清楚谁是谁的。
  4. 每个来源订单在这间房里有一个计费份额：默认第一张拖进来的单是 1（这张单掏钱），后面拖进来的单是 0（跟着住不额外收房费）。份额用房间盒子里的 − / ＋ 按钮调，每次 0.5 步进（比如两张单各半间就都改成 0.5）。保存时系统会校验：一间房里所有份额加起来必须等于 1，凑不齐会提示「计费份额合计须为 X，当前为 Y」并拦住保存。
  5. 三人间就是把三个人拖进同一个盒子：比如一张单 1 人、另一张单 2 人，份额可以是 1 + 0（第一张单出钱），也可以按实际约定改成别的比例，只要合计是 1。房型如果限 2 人、你拖进了 3 个人，系统只会在房间标题上标一个「超容量」提示，不会拦你保存——酒店那边给的是加床还是家庭房，运营自己判断，系统不替你决定对不对。
  6. 每个房间盒子下面有一个「备注」输入框，可以写房控自己的备注（比如"加床"）。
  7. 都拖好之后点右下角「保存」。保存成功会提示"已保存 · N 间房"；如果这期间别人也改过同一间房，会提示「该房间已被他人修改，请刷新」，点旁边的「刷新」重新拉一次最新状态再改。
  8. 保存之后，销控板的「物理房间」行和占房下钻抽屉会立刻反映新的分房结果：下钻抽屉里每张涉及跨单合住的订单会多一行"跨单合住 X 间 · 本单计费份额 X · 去重物理房 X"——这三个数口径不一样，不能直接拿来加减凑总数，本晚这家酒店的物理房间合计以销控板本身的"物理房间"行为准。

三人合住一间房：份额 1 + 0（第一张单出钱），房型限 2 人但拖进了 3 个人，标「超容量」提示（仅提示，不拦保存）

份额合计校验：如果手滑把某间房的份额调乱了（比如变成 1 + 0.5 = 1.5），点「保存」时不会真的提交，会先在原地报错「房间「标准房」的计费份额合计须为 1，当前为 1.5」，把份额改回合计等于 1 再保存即可。

四、几条要记住的规则

  1. 钱不自动重算。份额定好之后，系统不会自己去改结算价：份额是 0 的那张单如果本来就该少收钱，需要运营手动走「改结算价」把差额调过去；系统只保证"这间房算谁的、算几间"这件事，不替你算钱。
  2. 换酒店、改期、改档会自动解绑，并且会提示你。如果一张单的某个酒店行已经在跟别的单合住，这时候你去给这行换酒店、改入住日期、或者改套餐档次，系统会自动把这行从共享房里解绑（变回这张单自己的普通房间），不会拦你操作，但会弹提示告诉你"这里原来是跟别的单合住的，现在已经解开"。解绑之后如果这张单原来份额是 0，钱还是不会跟着自动变，需要你自己看要不要补结算价。
  3. 已经合住的行，不能直接改单住/拼住，也不能直接补单房差。要改这类操作，得先在跨单分房工作台里把这一行从共享房里解绑（或者整间解散），解绑之后再回订单详情去改单住、拼住或补房差。系统会用文字告诉你"该行与他单合住，请先在跨单分房里解除合住再改"。
  4. 旧订单要拉进共享房，得先把分房表里的房组都"认领"到具体的酒店行上。老单子如果分房表里的房间组没选归属的酒店行（这种情况在分房编辑器里能看到），跨单分房工作台会把这张单的人标成"锁定"、拖不进去，并提示「房组归属不完整，请先在分房编辑器给全部房组补齐归属订单行，才能拉进共享房」。回订单的分房编辑器里把归属选好、保存一次，就能正常拖进跨单分房了。
  5. 一方取消之后，房间不会自动腾出来。合住的两方里，如果掏钱那一方后来取消或者退款了，系统不会自动把这间房算成空的——物理房间数还是按 1 间占用算，房控页的「提醒线」会给一条「合住方已取消」的提示，列出还剩下谁在住，提醒房控去核对这间房要不要补钱、或者干脆解绑腾出来卖给别人。
  6. 代理看不到对方的单号。代理登录看自己的订单，如果这行房间是跟别的单合住的，代理只会看到"已与他单合住"这样一句话，看不到对方是哪张单、也拿不到对方的任何信息，保护双方隐私。

五、单单分房编辑器里的变化

从订单详情或者房控页「订单分房（拖拽）」进单张订单的分房编辑器，如果这张单的某个房间组已经在跨单分房里跟别的单合住了，这个房间盒子会带一个 🔒已与他单合住 的锁标签，锁定之后只能改这间房的备注——乘客拖不出来、也拖不进新的人，房型、归属都改不了，页面上也会提示"想调整请去房控页「跨单分房」"。想动这些内容，回跨单分房工作台去改。

六、导出：房号怎么印

分房表导出、整班机导出、全岗总表——这三个导出现在共用同一套房间编号：同一间共享房，不管哪一方份额多少，三份表印出来都是同一个房号，不会因为一方份额是 0 或者 0.5 就印出不一样的后缀。备注列会自动写上"与 FTM… 合住"，把合住对方的单号列出来（代理侧导出不写对方单号，只写"与他单合住"）。

七、常见问题 Q&A

问题怎么办
保存时提示"该房间已被他人修改，请刷新" 说明你打开工作台之后，另一个人也保存过同一间房。点提示旁边的「刷新」按钮重新拉一次最新状态，之前的拖拽改动会丢，需要照最新状态重新拖一次再保存。
保存时提示"计费份额合计须为 1，当前为 X" 把这间房里各订单的份额用 −/＋ 调整，合计凑到 1 再保存（比如 0.5+0.5、1+0，或者三方 0.5+0.5+0 之类，只要加起来等于 1）。
某张单的人在池子里显示"锁定"，拖不进房间 这张单的分房表里有房间组还没选"归属酒店行"。先去这张单的分房编辑器，把所有房间组都指定好归属的酒店行并保存，回到跨单分房工作台刷新一下就能拖了。
想把已经合住的一间房拆散，各自单住 回到跨单分房工作台，找到这间共享房，点右上角「解散整间」。解散之后每张单的人各自变回自己单里的普通房间组，计费份额、房型都保留在各自单上，需要再手动调整。
三人间到底怎么处理 正常拖：把三个人（不管来自几张单）拖进同一个房间盒子，份额合计等于 1 即可保存；房型如果限 2 人会提示「超容量」，不影响保存，酒店那边是不是真的能加床、要不要另收加床费，运营自己判断和沟通。
换了酒店/改了期之后，原来合住的份额去哪了 系统会自动把这一行从共享房解绑，变回这张单自己的普通房间组（计费份额跟着这行走，不会凭空消失），并弹提示告诉你已经解绑。共享房里剩下的其他单不受影响，除非解绑之后房间只剩这一方，那就自动整间解散。
某张单的一条酒店行，一部分乘客在共享房里、剩下的还是普通房间组，为什么拆单会报错 系统不知道普通房组那部分该跟着搬走几间，怕算错悄悄覆盖运营的输入，所以直接拒绝，不猜。两条出路：①先在跨单分房工作台把这条行剩下的普通房组也并进同一间共享房，让整条行都是共享成员；②先把共享成员解绑回普通房组，再拆单。如果本单在这家酒店还有别的行，也可以把普通房组挪到那一行。
分房表、全岗总表、房控核对表几张表的房号对不上，是系统错了吗 通常不是。两种常见原因：①几张表不是同一批时间导出的——中间如果有人改过分房，房号自然会对不上，重新对齐导出时间点再比对即可；②有些历史存量房间组没有归属到具体订单行（老数据），全岗总表这类表只能按酒店名文本把它们分桶，跟分房表 / 整班机按订单行归属分桶不是同一套口径，两边偶尔对不上号是预期内的，不影响新建的共享房（新建的都带订单行归属）。
以下两类场景本说明按规格要求覆盖，但测试库目前没有能触发的真实数据，截图从缺，效果以文字为准：
  • 「保存冲突」的 409 提示（"该房间已被他人修改"）——需要两个人同时改同一间房才能真实触发，测试库单人操作复现不了，实际提示文案见上方 Q&A 第一条。
  • 房控页「提醒线」里的「合住方已取消」——测试库当前没有"掏钱一方已取消、对方仍在住"的存量数据，效果见§四第 5 条的文字说明。

八、本次同步上线的相关变化

  • 普通房组不再跨单同名合桶。以前系统里如果两张不同订单的房间组"酒店名+房型+日期"完全一样，统计的时候可能被当成一桶合并计数；现在普通房组严格按各自订单单独计数，真正要合住必须走「跨单分房」显式指定，不再"看着像"就合并。
  • 提醒线新增"部分未分房"。如果一张订单已经有酒店行，但里面还有乘客一个房间组都没进（既没进普通房组，也没进共享房），提醒中心会提示出来，方便房控收尾。
  • 房控提醒线新增"合住方已取消"。见§四第 5 条：掏钱一方取消/退款之后，共享房不会自动腾空，会在这里提示核对。
