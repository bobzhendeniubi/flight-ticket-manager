## 不 counter 口径的具体做法

- B2：`SettlementRate`/`SettlementDiscountRule` 加 `routeKey`，迁移给存量行写 `MFM-DAD`，唯一键扩为含 routeKey；取价按套餐绑定航班派生 routeKey，找不到航线的套餐不再命中任何日历价（而不是回落到岘港）。0811 滚动窗口、0828 每人结算价、0903 代理自助结算价逻辑不碰。
- B3：随机档聚合/缺口按 `cityCode` 圈定，城市由套餐绑定航班的目的地推导；0902「随机档是需求池」口径不变，仍不闸单只记缺口。
- S2：全部改走 `lib/flight-time.ts`，与 0823 航班时刻口径一致。
- 提醒：0830 知会过「首按会冒大量存量待办」，自动跑首日只推 CRITICAL。
- 航线派生单一入口：`backend/src/modules/products/bundle-route.ts`（`resolveBundleRoute` / `bundleRouteKey`），所有按航线取数的地方都从这里拿，不再各写一份。

## 并行分支纪律

- 每个子代理独立 worktree + 独立本地数据库 `ftm_wt_<分支>`，避免迁移互相打架。
- 一个关注点一个 commit；不 push；不 ssh；不部署。
- 合并顺序：先 schema/迁移类（B2、B3、Refund 字段）→ 再服务层 → 最后前端；合并后整体跑三闸 + 集成测试。
