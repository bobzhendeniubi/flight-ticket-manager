## 上线前一次性动作（服务器）

1. **迁移前置检查**（实测库）：`SELECT "originCode","destinationCode",count(*) FROM "Flight" WHERE "isActive" GROUP BY 1,2;` —— MFM→DAD 与 DAD→MFM 各应恰好 1 条，存量套餐才会被自动绑航班；否则迁移不动，需运营在「产品 · 套餐」手工绑。
2. **迁移后检查**：`SELECT code,name FROM "Bundle" WHERE "isActive" AND "outboundFlightId" IS NULL AND "returnFlightId" IS NULL;` —— 应为空；有结果的套餐前台/录单都不可售，先绑再上架。
3. `.env.prod` / `.env.staging` 加 `SMOKE_EMAIL` / `SMOKE_PASSWORD`（建一个只读够用的 ADMIN 号，别用真人号）；不配则冒烟只探 `/readyz`。
4. `.env.prod` / `.env.staging` 加 `WECOM_WEBHOOK_URL`（企业微信群机器人）；不配即 no-op。
5. 第一次跑新 `deploy.sh` 走完整流程即可（自动打 git-sha tag，写 `.deploy-history`）；以后 `deploy.sh rollback <env>` 秒级回滚（有新增迁移时拒绝，`--force` 放行）；`--no-auto-rollback` 关闭冒烟失败自动回滚。
6. 功能开关顺序（后台「系统 → 功能开关」，ADMIN）：先全关部署 → 配 webhook → 测试站先开 `REMINDER_WEBHOOK_PUSH` 看消息落群 → 开 `REMINDER_AUTO_GENERATE`（首日存量多，只推 CRITICAL，已在汇总里注明）→ 最后开 `REMINDER_BELL_ALL`。
7. 财务页「待打款」页签首次打开会一次性涌入全部存量已核准退款（`paidAt` 未回填），需财务逐笔核对补登记。

## 部署知会（按岗位）

**运营**
- 套餐**必须绑去程航班号**，否则整段日期不可售（前台「暂未开放预订」，录单提示先绑航班）。
- 建班次要选时区：该航班已有班次的沿用最近一班；全新航班第一班要选出发/到达时区。
- 按日期搜航班 / 座位统计现在按每班自己的时区算当地日，深夜凌晨班次归属日可能与以前差一天，是纠正。
- 结算价日历 / 立减规则页多了「航线」下拉，存量全部自动归 MFM-DAD 不用重录；粘贴报价表前先选航线；新线开通后先建航班再填日历。
- 新页「导出中心」（侧栏概览组）把 18 个导出按岗位列全，原按钮都还在。
- 录单成功页多「复制上一单」（保留代理/联系人/四类备注/签证状态/结算价模式，清乘客）；订单详情多「以此单为模板新建」。
- 仪表盘显示「提醒上次生成：x 小时前」，超 24 小时标琥珀。

**财务**
- 认款「自动配对建议」改由服务端算：备注里的订单号 / 姓名 / 代理 / 手机尾号会被识别并标出理由；高置信度仍需人勾选后点认款，系统不自动入账。
- 有意收紧：金额恰好相等但备注**没有任何身份线索**的，从「一键」降到中档，要「选中并定位」再拖一下，防同额撞单。候选回看近 90 天；多笔凑一单 / 一笔付多单作为组合建议单独展示。
- 财务页多「待打款」页签（已核准未打款的退款）+「标记已打款」；重复标记 409 并显示上次登记人。
- 代理对账单**按出发日归月**，与结算单按下单日归期是两个口径，表头已注明。
- 结算价审计标签带航线（如 `MFM-DAD/CITY_3STAR/2晚/…`）。

**房控**
- 房控页顶部多「城市」下拉；销控矩阵与房态导出按城市分块；加房清单一天一城一行；提醒标题带城市（「岘港三星随机 9/6 缺 1 间」）——别在别的城市加房。
- 建 / 改占位酒店必须填城市；城市代码可直接输入新码。

**代理**
- 前台「我的分成」可按月下载对账单（不含成本与证件）。

**票务**
- 整班灌票号走导航「票号回填」：选班次贴名单（`护照号或姓名, PNR, 票号`，逗号 / Tab / 空格都认，也能传 xlsx）；系统里已有且不一样的号标琥珀、默认不勾，确认要换才打开「允许覆盖已有票号」。
- 订单详情乘客卡可直接改单人 PNR / 票号（留空不动、清空二次确认）。
- **回填不会给客人发行程单**，要发去订单详情点「重发行程单邮件」。
- 沙箱开关 `ENABLE_AUTO_FULFILLMENT` 未动（待拍板）；线上 32/32 假号回填时全部走「覆盖」路径。
