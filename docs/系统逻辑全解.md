# 系统逻辑全解（2026-07-14 五路审计合成版）

> 依据 HEAD `233f21c` 的五路代码审计（套餐不变式 / 钱流 / 订单生命周期与座位账 / 履约与导出 / 渠道与权限）合成。
> 每条结论都有代码证据，审计原始报告见各批次会话记录。破口清单在末章按优先级排序。

## 0. 一句话模型

**产品有各自的真实库存 → 三个卖场把它们卖出去（套餐只是打包定价的购物袋）→ 每张订单沿一条状态机走完一生 → 全程拖着三条河：钱流（应收/实收/退款/佣金）、库存流（座位/房）、履约流（票务/房控/签证/接送四个岗位的任务）。三条河必须永远同步——所有破口本质上都是某条河断流。**

## 1. 卖之前：产品与库存

| 库存 | 机制 | 状态 |
|---|---|---|
| **机票座位**（班次×舱位） | 物化计数器 sold；下单原子 CAS 扣座（`sold+qty+他人锁位≤capacity`）；取消/超时/退款按状态机自动还座 | 健全 |
| **酒店包房**（酒店×房型×晚） | 派生账（无计数器，每次现查订单占用）：包房 block vs 用房床位（0.5 拼房）vs 物理房间（按性别 ceil，异性不拼）vs 余量（物理口径） | 健全 |
| **开票额度**（班次） | ticketingCap 默认 191——占座≠能开票的第二本账，翻"已开"时同事务校验 | 健全（但无前端配置入口；取消单占额不释放） |
| **座位锁**（SeatLock） | 下单前 10 分钟临时锁位，惰性过期，正确性不依赖 worker 准时 | 健全 |
| **候补**（SeatWaitlist） | 只做"有票通知"（座位释放时触发），不占不扣 | 通知闭环在，转正靠人工 |
| **切位**（SeatAllocation 包位） | **零成品**：schema 无模型，仅 TODO 注释+stash | 缺件（包机模式的本命功能） |
| 签证 / 接送 | 无库存，纯履约服务 | 设计如此 |

**套餐不变式（老板拍板）**：套餐=购物袋，卖一个套餐=卖出袋里每个真实产品，每个组件必须砸到自己的库存/履约流。套餐只负责打包定价（组件加总×折扣）+ 一个订单号。定价侧已达成（前后台同源、逐分核账）；库存侧的破口见 §9-P0-4。

## 3. 订单的一生（状态机）

```
录单（唯一入口 createOrder，落 PENDING_PAYMENT，同事务原子扣座）
  ├─ 30min 未付（仅散客）→ PAYMENT_TIMEOUT（还座）→ 可拉回 PENDING_PAYMENT（重占座）/ CANCELLED
  ├─ 取消 → CANCELLED（还座，终态）
  └─ 收款满 → PAID（建齐履约任务+计提佣金）→ PROCESSING → TICKETED → COMPLETED（终态）
        ├─ 申请退款 → REFUND_REQUESTED —批准→ REFUNDED（还座+冲佣金+退款完成，终态，force 也不能复活）
        │                       └—拒绝→ PROCESSING（⚠️ 退款申请记录卡死，P1-7）
        ├─ 申请改签 → CHANGE_REQUESTED → CHANGED / 驳回回 TICKETED
        └─ 失败 → FAILED（还座，可修复/取消/退款）
```

- 13 个状态被"占座 8 态 / 释放 5 态"完全瓜分，无死区；每次流转原子 CAS 防并发。
- 释放型流转自动：还座（有下限保护）+ 冲佣金（按实退比例/全额）+ 同步退款单状态。
- 软删=回收站（仅 ADMIN；必须已还座+净收款≤0），恢复不凭空占座；软删单从一切列表/导出/统计消失（但按 id 直查仍可见）。
- 售后操作：改期（先还旧座再原子拿新座）、换人（清 18 个身份字段）、换酒店（差价+房控自动跟）、改归属（财务不回溯）、补房差（FEE 行）。事后调价通道在票务二轮批规划中。

## 4. 钱流

**应收**：`应付 = 订单总额(total) + 售后调整(adjustmentCny)`；`尾款 = 应付 − 已付`。改应收只有四条结构化通道（录单调价行 / 机票行改结算价 / 补房差 FEE 行 / 改期换人换酒店费），全部 ADMIN/STAFF + 审计。

**收款三条路**（共用同一行锁事务内核，幂等键防重）：
1. 网关支付（验签+金额比对，订单已死则标原路退回）
2. 人工确认收款（缺省金额=尾款、允许多付、防手误上限、分笔天然支持、批量到账逐单独立）
3. 挂账池认领——挂账池（Receipt）三个进口：财务登记转账 / 客户上传凭证（仅声明不入账）/ 订单多付转入；出口：认领到订单（全有或全无）或标记退款（线下打款）。

**代理的钱**：预存余额唯一正道=认款（凭证→财务确认→流水+幂等锚），余额永不为负；抵扣尾款走 OFFSET 流水、抵满自动转已付；佣金=层级价差模型（每级拿自己费率−下级费率的差），PAID 时计提、幂等、退款按比例冲、已结算走负数补偿绝不改历史；结算单每代理每月一张，转"已付"前强制余额复核。

**退钱**：取消手续费按政策阶梯（距起飞小时数踩档，已履约/无政策=100%）；退款完成只记义务不减已付、真打款在线下；净收款>0 禁删单。

**对账工具**：预期到账（出纳手账，锁定仅 ADMIN）、审计日志（资金类动作全记）、收款对账台总账、财务导出（含成本毛利）。

**十条钱铁律**（8 条成立，2 条被 P0-2/P0-3 打破）：应收只走结构化通道；实收只在行锁事务内经统一内核；余额永不为负必有流水；一笔钱最多入账一次；挂账认领全有或全无；佣金冻结快照负数反冲；结算单终态；净收款>0 禁删+退款单禁复活；散客 30 分钟后台永不；客户上传只是声明。

## 5. 卖之后：四个岗位

**票务岗**：开票=三维布尔（去程/回程/系统），按航段分别向航司提名单出票；翻"已开"同事务校验班次额度；筛选（出行日期单日/航班号/开票状态）→ 导出票务模版（27 列航司格式，一格不能动）→ 回填开票状态。PNR/票号：demo worker 自动出票写回乘客。

**房控岗**：配包房周期（切了多少间）→ 销控矩阵四行（包房/用房床位/物理房间/余量-物理口径，异性不拼间）→ 提醒线（超卖加房/富余退房/班次超上限/拼房落单）→ 分房表（人工拖拽优先，未分房按性别自动打包）→ 导出（房态/分房表 19 列旧格式/护照包按酒店或按姓名）。

**签证岗**：任务三重触发（订单签证状态=需要 / 签证行 / 套餐含签证组件），下单即进台不等付款；自备签乘客自动排除；状态四档筛选+签发方式筛选（电子/贴纸/落地）+备注对账（批量备注+搜索）；名单表与护照包分开下载。

**操作部**：提醒中心 4 条规则（催尾款/出行提醒/护照临期/签证缺件），手动生成、站内可见、无外发通道（短信/邮件是占位）。

## 7. 权限与渠道

- 角色四档：ADMIN（全能+force+软删+财务报表）> STAFF（运营全套，不能停用代理/锁预期到账/看财务 P&L）> AGENT（自己+下级树内：看单/建单/申请退改/建下级/认款）> CUSTOMER（本人单+受限流转）。
- 代理树：自关联最多 5 级，可见性=自己+后代闭包（递归 CTE），越界 403；佣金链费率不变式 child≤parent；停用不级联、仅登录时拦截。
- 脱敏：外部角色（AGENT/CUSTOMER）订单序列化统一剥离内部备注/提醒/预期到账/调整流水/认领人/代理余额/逐行单价/计价 metadata/护照大图；公开查单另有更狠的打码视图。
- 产品成本仅 ADMIN/STAFF 可见（班次成本对代理有 4 字段漏剥 → §9-P1-6）。

## 9. 破口总清单（按优先级）

### P0 —— 钱/库存正确性，立刻修
1. **改期无占座状态守卫**：可对已取消/退款/软删单改期 → 旧班次座位被二次释放（且该路径无下限保护可打成负数）、新班次凭空占座挂死单上永无人释放。一次误操作两边座位账同时坏。
2. **代理余额凭空造**：建下级代理可直接填初始余额（0~1000万），无流水无审计，**AGENT 自己就能操作**——凭空钱可抵尾款/进结算。
3. **改状态=隐式收款**：状态推到已付时系统自动把已付抬到全额，无任何收款凭证，实收与流水必然对不上。
4. **批量创单套餐不占座**（+房控盖章依赖套餐默认出发日；最坏组合=零座位零房控的"裸单"）。修复路线已定：后端按套餐绑定航班+日期匹配班次注入真机票行，逐单走单笔同一条定价+盖章+占座链路（释放侧状态驱动自动对称）。

### P1 —— 对账/越权/一致性，尽快
5. 备注接口越权（IDOR）：任意登录用户可覆写任意订单备注（无归属校验）。
6. 班次成本 4 字段对代理泄漏（燃油/旺季/机型调整/起降折扣）——可反推毛利。
7. 拒绝退款后申请记录卡死 → 客户再也无法发起取消；未来真退款用陈旧快照算冲销。
8. 换人清洗不全：新旅客继承旧人 PNR/票号（行程单照印）、自备签标记（签证台漏人）、国籍。
9. 售后费（adjustmentCny）被全部导出+财务模块忽略——改期费/换人费从报表消失。
10. 财务收入含未付订单、先收后退的单整单蒸发（应记负项）——收入与实收长期不可对平。
11. 开票占额不排取消单——死单永久占用班次 191 上限。
12. 批量到账无幂等键——重复提交双倍入账（单笔有防护）。
13. 自备签只挡签证台显示：送签名单/护照包/缺件提醒仍把自备签客人算进去催材料。
14. 状态机不设防软删单：可 force 出"占着座位但报表全隐身"的订单。

### P2 —— 口径统一/体验
15. 导出口径不一致 10 项（最疼三个：全岗总表"开票状态"列读旧字段——六态开票后**显示恒错**；尾款列不含售后调整；结算价两套均摊算法）。
16. 履约任务无终态化（订单死了任务只是被过滤隐藏，force 拉回即复活）。
17. 改结算价按钮漏 STAFF；改期不同步酒店入住日；超时单拉回后无超时保护。
18. 余额流水/挂账无查询界面；开票上限无前端入口；提醒无推送通道；停用代理存量 token 不失效。
19. 技术债：COUNTED_STATUSES 复制 ~10 处、代理树实现 3 份、新旧开票双轨。

## 10. 全系统不变式（浓缩版，验收新功能用）

1. 套餐=购物袋：每组件必砸真实库存/履约流。
2. 权威定价唯一源：服务端重算，改价只走结构化通道+审计。
3. 座位账：占/释 13 态全覆盖、原子 CAS、有下限、与入口无关。
4. 钱：应收结构化、实收进内核、一笔钱最多入账一次、佣金快照冻结。
5. 可见性：代理=自己+后代闭包；外部角色字段过脱敏白名单；成本绝不出内网角色。
6. 每（订单项×任务类型）至多一条履约任务；任务必须来自活订单。
7. 开票额度=座位之外的第二本账，翻位必校验。
8. 异性不拼一间（销控/分房/提醒三处同口径）；未知性别保守独占。
9. 导出绝不编造：没有的数据留空列；全表排除取消族+软删。
10. 三流同步：任何售后变更必须同时落 钱+库存+履约（未来"编辑订单"的验收标准）。
